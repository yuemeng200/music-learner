# 设计方向与 Skill 使用策略

## 1. 设计目标

这个网站的视觉目标不是“漂亮的课程页面”，而是一个让音乐知识显得可触摸、可探索、可感知的高级互动学习空间。整体应更接近艺术展览中的声音装置，而不是传统网课平台。

用户进入网站后应立即感受到：

- 这是一个严肃但不枯燥的音乐学习产品。
- 音乐理论不是教材文字，而是可以被听见、被操作、被比较的结构。
- 页面设计本身像一个精致的音乐工作台，而不是传统网课平台。
- 页面有足够的沉浸感，让用户愿意停留、探索和反复试听。

## 2. 已安装的设计 Skill

### 2.1 `frontend-design`

来源：

- `anthropics/skills@frontend-design`
- 安装位置：`~/.agents/skills/frontend-design`

用途：

- 用于早期视觉概念探索。
- 帮助避免通用 AI 风格页面。
- 在实现首页、课程界面、互动组件时，用它确定强烈但统一的审美方向。

适用阶段：

- 视觉概念稿。
- 首屏体验。
- 核心互动页面。
- 设计系统初稿。

### 2.2 `high-end-visual-design`

来源：

- `leonxlnx/taste-skill@high-end-visual-design`
- 安装位置：`~/.agents/skills/high-end-visual-design`

用途：

- 用于提升高级感、空间感、动效节奏和细节质感。
- 适合在已有页面结构后做视觉升级。
- 重点参考它的高端视觉反模式检查，例如避免平庸网格、默认字体、廉价阴影、无意义动效。

适用阶段：

- 高保真 UI。
- 动效设计。
- 微交互设计。
- 视觉打磨。

### 2.3 `web-design-guidelines`

来源：

- `vercel-labs/agent-skills@web-design-guidelines`
- 安装位置：`~/.agents/skills/web-design-guidelines`

用途：

- 用于实现后的 UI 审查。
- 检查布局、可访问性、交互反馈、响应式和工程质量。
- 它更像质量门槛，不负责定义视觉风格。

适用阶段：

- 页面实现后。
- PR 或提交前。
- 响应式与可访问性检查。

### 2.4 `ui-ux-pro-max`

来源：

- 当前环境已存在。

用途：

- 用于产品体验结构、信息架构、交互控件选择和可用性约束。
- 它适合做理性层面的 UX 判断，和上面几个视觉 Skill 互补。

## 3. 推荐设计路线

### 3.1 产品审美关键词

建议采用：

- 精密。
- 沉浸。
- 清晰。
- 声音可视化。
- 类音乐工作站。
- 艺术展览感。
- 轻微舞台感。
- 教育产品的可读性。

避免：

- 儿童化卡通风。
- 传统网课平台风。
- 过度赛博朋克。
- 纯黑大屏数据看板。
- 装饰性渐变堆叠。
- 大量无意义玻璃拟态。

## 4. 页面设计原则

### 4.1 课程界面优先像工具，不像文章

课程页面的核心应是互动区域。文字说明必须服务于当前操作，不应压过声音实验本身。

### 4.2 音乐概念必须有视觉映射

示例：

- 音高：垂直位置、键盘位置、频率曲线。
- 音程：两个点之间的距离、半音阶路径。
- 和弦：多个音点形成的结构。
- 节奏：时间网格、播放游标、重音层级。
- 调性：中心音的引力关系。

### 4.3 高级感来自控制，不来自堆料

高级设计应体现在：

- 字体层级稳定。
- 颜色克制但有明确功能。
- 动效和声音播放同步。
- 交互反馈准确。
- 留白服务于注意力。
- 控件看起来像真实工具，而不是装饰卡片。

## 5. 后续使用方式

在正式实现前，建议先产出三个设计文档：

1. `docs/COURSE_SPEC.md`：每节课的文案、互动步骤、反馈逻辑。
2. `docs/INTERACTION_MODEL.md`：键盘、节奏网格、旋律编辑器等核心组件的状态模型。
3. `docs/VISUAL_SYSTEM.md`：字体、颜色、布局、动效、声音可视化规则。

实现时的 Skill 使用顺序：

1. 用 `ui-ux-pro-max` 梳理体验结构。
2. 用 `frontend-design` 确定核心视觉概念。
3. 用 `high-end-visual-design` 打磨高保真表现。
4. 用 `web-design-guidelines` 做实现后的质量审查。
