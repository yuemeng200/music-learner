# 互动式音乐理论学习网站 PRD

## 1. 产品定位

本产品是一个面向大众的互动式音乐基础素养网站。它不是一本线上乐理教材，也不是一个功能复杂的编曲软件，而是一套短小、连贯、可操作的音乐认知课程。

用户完成整套课程后，应获得一套清晰的音乐基础认知：

- 音乐不是抽象规则的堆积，而是声音之间关系的组织。
- 音高、节奏、音程、和弦、调性、旋律、织体这些概念彼此连接。
- 乐理概念不是为了考试背诵，而是为了帮助人更准确地听、理解、表达和创作音乐。
- 用户可以用基础术语描述自己听到的东西，并能进行非常简单的音乐构造。
- 用户最终可以通过一个小型音乐编辑器，把所学知识组合成一个短小音乐片段。

## 2. 目标用户

### 2.1 核心用户

- 完全没有系统学过音乐理论，但对音乐有兴趣的人。
- 会听歌、可能会唱歌或弹一点乐器，但无法解释音乐为什么这样听起来的人。
- 想进入创作、编曲、作曲、乐器学习或音乐欣赏，但缺少入门框架的人。
- 希望提升音乐美学与音乐素养的人。

### 2.2 非目标用户

- 已有扎实乐理基础、需要高阶和声或作曲训练的人。
- 需要考级、艺考、专业院校系统教材的人。
- 只想查询术语定义的人。

## 3. 产品目标

### 3.1 学习目标

用户完成课程后，应能做到：

- 听出音高变化、节奏变化、音程差异和基础和弦色彩。
- 理解十二平均律、半音、全音、音名、音阶的基本关系。
- 理解音程不是距离名词，而是两个音之间的听觉关系。
- 区分大三和弦、小三和弦、属七和弦等基础和弦的色彩。
- 理解调性中心的作用，知道为什么同样的音在不同上下文中会产生不同感觉。
- 用简单节奏和音阶材料写出一小段旋律。
- 用“节奏、音高、和声、调性、结构”等维度分析一段简单音乐。
- 看懂非常基础的五线谱，理解它如何表达音高、节奏和旋律。
- 在最终小型编辑器中完成一个短小音乐片段。

### 3.2 产品体验目标

- 每个概念都必须通过可听、可点、可修改的互动体验呈现。
- 每节课控制在 5 到 10 分钟内。
- 每章结束时用户都应完成一个小作品或小判断，而不只是读完文字。
- 用户不需要提前知道五线谱，但课程中会引入最基础的读谱能力。
- 所有术语都应在用户已经听到或操作过对应现象之后再引入。
- 中文术语与英文术语并行保留，但不在主界面堆叠。

## 4. 核心设计原则

### 4.1 先体验，后命名

先让用户听到、改变、比较，再告诉用户这个现象叫什么。例如先让用户听 C 和 E 的关系，再引入“大三度”。

### 4.2 少讲定义，多做比较

音乐认知来自差异。每个知识点都应提供 A/B 对比，例如大三和弦与小三和弦、强拍与弱拍、稳定音与不稳定音。

### 4.3 每章只有一个核心问题

每章围绕一个问题展开，例如：

- 为什么有些音听起来更高？
- 为什么两个音放在一起会有不同感觉？
- 为什么三个音可以形成“明亮”或“忧郁”的色彩？

### 4.4 课程短，但认知链完整

课程不追求覆盖所有乐理术语，而是建立一条完整链路：

声音 -> 音高 -> 音程 -> 音阶 -> 和弦 -> 调性 -> 节奏 -> 简单记谱 -> 旋律 -> 简单分析与创作

## 5. 课程总结构

建议第一版课程包含 10 章（编号 0–9），每章 3 到 5 个互动小节。

### 第 0 章：音乐不是规则，是可组织的声音

核心问题：音乐理论到底在解释什么？

学习目标：

- 建立“音乐由声音关系构成”的总体认知。
- 让用户知道后续课程会从听觉体验出发。

课程内容：

- 听一个单音。
- 听两个音。
- 听三个音。
- 听一段节奏。
- 听一小段旋律。

互动设计：

- 页面提供 5 个声音按钮：单音、音程、和弦、节奏、旋律。
- 用户点击后，界面用不同方式高亮声音中的元素。
- 最后给出一句总结：后面的课程会把这些元素逐个拆开。

产出：

- 用户完成一个“我听到了什么”的快速选择题，不要求答对，只用于建立感知入口。

### 第 1 章：音高，声音的上下方向

核心问题：为什么我们会觉得有些音高、有些音低？

学习目标：

- 理解音高与频率相关。
- 理解音名只是给音高位置起的名字。
- 初步认识键盘上的 12 个音。

课程内容：

- 高频与低频。
- 音名：C D E F G A B。
- 黑键与白键。
- 半音与全音。
- 八度。

互动设计：

- 虚拟键盘：点击任意键播放声音。
- 音高滑杆：拖动滑杆改变频率，观察音高变化。
- 键盘高亮：展示 C 到下一个 C 的八度关系。
- 半音路径：用户按顺序点击相邻键，看到 12 个半音。

产出：

- 用户能在键盘上找到两个 C，并理解它们“名字相同但高度不同”。

### 第 2 章：音程，两个音之间的距离和表情

核心问题：为什么两个音之间会产生不同感觉？

学习目标：

- 理解音程是两个音之间的关系。
- 能听出若干关键音程的色彩差异。
- 知道半音数量会影响音程名称和听感。

课程内容：

- 同音、半音、全音。
- 小三度、大三度。
- 纯四度、纯五度。
- 八度。
- 协和与紧张的初步感受。

互动设计：

- 双音选择器：用户选择根音和第二个音，系统播放并识别音程。
- A/B 对比：连续播放小三度和大三度，让用户选择哪个更明亮。
- 盲听小游戏：播放一个常见音程，用户从两个选项中判断。

产出：

- 用户能把音程理解为“两个音的听觉关系”，而不是只记名称。

### 第 3 章：音阶，给旋律划定一个声音世界

核心问题：为什么某些音组合起来像一个统一的世界？

学习目标：

- 理解音阶是一组被选中的音。
- 理解大调音阶的全全半全全全半结构。
- 初步理解小调与大调的色彩差异。

课程内容：

- C 大调音阶。
- A 小调音阶。
- 全音与半音的排列。
- 音阶与旋律材料。

互动设计：

- 音阶点亮器：在键盘上高亮当前音阶包含的音。
- 音阶播放：上行、下行播放音阶。
- 色彩对比：同一段节奏分别使用大调和小调音阶播放。
- 限制创作：用户只能用当前音阶内的音写 4 个音。

产出：

- 用户完成一个 4 音小旋律，并能听出大调和小调气质差异。

### 第 4 章：和弦，多个音一起形成的色彩

核心问题：为什么三个音一起按下去会有稳定的情绪色彩？

学习目标：

- 理解三和弦由根音、三音、五音构成。
- 区分大三和弦、小三和弦、减三和弦的基础听感。
- 理解和弦可以从音阶中生长出来。

课程内容：

- C 大三和弦：C E G。
- C 小三和弦：C Eb G。
- 根音、三音、五音。
- 和弦转位的初步体验。

互动设计：

- 和弦构建器：用户在键盘上选择 3 个音，系统识别和弦。
- 一键切换：C 大三和弦与 C 小三和弦快速对比。
- 和弦拆解：先依次播放三个音，再同时播放。
- 转位按钮：改变音的排列，听出“同一个和弦，不同位置”。

产出：

- 用户能解释大三和弦与小三和弦的区别主要来自中间那个音。

### 第 5 章：调性，音乐里的家

核心问题：为什么有些音听起来像“回家了”？

学习目标：

- 理解主音和调性中心。
- 理解稳定与不稳定。
- 初步理解和弦进行为什么会产生方向感。

课程内容：

- 主音。
- 属音。
- 终止感。
- I、IV、V 和弦的基础功能。

互动设计：

- 回家实验：播放一段未解决旋律，让用户选择结尾音，体验哪个更稳定。
- 和弦进行播放器：I-IV-V-I、I-V-vi-IV 等基础进行。
- 稳定度标记：用户点击音阶内不同音，界面显示相对稳定程度。

产出：

- 用户能理解“调”不是一组符号，而是一个听觉中心。

### 第 6 章：节奏，时间里的组织方式

核心问题：为什么同样的音，用不同节奏会完全不同？

学习目标：

- 理解拍、速度、强弱、节奏型。
- 区分四分音符、八分音符的基本时间关系。
- 感受切分和重音带来的律动变化。

课程内容：

- BPM。
- 拍号的基础概念。
- 四分音符、八分音符。
- 强拍与弱拍。
- 切分。

互动设计：

- 节奏网格：16 格循环，用户点亮格子创建节奏。
- 速度滑杆：调整 BPM。
- 重音开关：开启或关闭强拍高亮。
- A/B 对比：规则节奏 vs 切分节奏。

产出：

- 用户做出一个 1 小节循环节奏，并能听出重音位置改变带来的差异。

### 第 7 章：旋律，把音高和节奏连成一句话

核心问题：为什么一串音会像一句有方向的话？

学习目标：

- 理解旋律由音高走向、节奏和停顿构成。
- 感受级进、跳进、重复、变化。
- 用有限材料写出一小句旋律。

课程内容：

- 上行、下行、波浪形旋律。
- 重复与变化。
- 句子与停顿。
- 旋律落在主音上的完成感。

互动设计：

- 旋律编辑器：用户在音阶网格中放置音符。
- 轮廓视图：用线条显示旋律上行、下行和跳进。
- 完成感实验：同一旋律替换最后一个音，比较稳定程度。

产出：

- 用户完成一段 2 小节旋律，并能说明它哪里重复、哪里变化、哪里结束。

### 第 8 章：简单记谱，为什么音乐需要被写下来

核心问题：五线谱到底在记录什么？

学习目标：

- 理解五线谱是记录音高和时间的工具。
- 看懂最基础的高音谱号、音符位置和时值。
- 知道五线谱不是音乐本身，而是描述音乐的一种方式。

课程内容：

- 五线和间。
- 高音谱号。
- C D E F G 的基础位置。
- 四分音符、二分音符、全音符的简单时值。
- 小星星等极简旋律片段。

互动设计：

- 谱面与键盘联动：点击谱面音符时，键盘同步高亮并播放声音。
- 音符落点实验：用户把一个音拖到不同线/间，听到音高变化。
- 节奏时值对比：同一个音分别用四分、二分、全音符播放。
- 简单读谱挑战：给出 3 到 5 个音，用户在键盘上按出对应旋律。

产出：

- 用户能看懂并播放一小段非常简单的五线谱旋律。

### 第 9 章：把一首歌拆开听，并做一个小片段

核心问题：学完这些概念后，我们如何重新听懂一段音乐？

学习目标：

- 把前面知识合并成一个分析框架。
- 能从节奏、旋律、和声、调性几个角度描述音乐。
- 完成最终小作品或小分析。
- 使用小型音乐编辑器完成一个 1 到 4 小节的短片段。

课程内容：

- 听一段短音乐。
- 标记主节奏型。
- 找到调性中心。
- 观察旋律轮廓。
- 听出和弦色彩变化。

互动设计：

- 分层播放器：分别开关鼓点、低音、和弦、旋律。
- 分析标记：用户在时间线上标记“节奏变化”“和弦变化”“旋律结束”。
- 最终挑战：给定音阶与节奏格，创作一个短 loop。
- 小型编辑器：组合节奏、和弦、旋律并实时播放。

产出：

- 用户完成一次简单分析，或创作一个包含节奏、和弦和旋律的 4 小节 loop。

## 6. 课程交互组件清单

### 6.1 虚拟键盘

用途：

- 音高、半音、全音、八度、音程、音阶、和弦教学。

关键能力：

- 点击播放单音。
- 支持高亮指定音。
- 支持显示音名。
- 支持限制可用音集合。
- 支持多音同时播放。

### 6.2 音程选择器

用途：

- 展示两个音之间的关系。

关键能力：

- 选择根音和目标音。
- 显示半音数和音程名称。
- 支持先后播放与同时播放。
- 支持听辨练习。

### 6.3 和弦构建器

用途：

- 教学三和弦、七和弦、和弦色彩。

关键能力：

- 用户自由选择多个音。
- 自动识别基础和弦。
- 展示根音、三音、五音。
- 支持和弦转位。

### 6.4 节奏网格

用途：

- 教学拍、速度、强弱、节奏型。

关键能力：

- 8 或 16 格循环。
- 点击开启或关闭格子。
- 支持 BPM 调整。
- 支持重音设置。
- 支持循环播放。

### 6.5 旋律编辑器

用途：

- 教学旋律、音阶应用、乐句。

关键能力：

- 横轴表示时间，纵轴表示音高。
- 用户放置、移动、删除音符。
- 支持当前音阶限制。
- 播放时高亮当前音符。
- 显示旋律轮廓。

### 6.6 分层播放器

用途：

- 最终综合分析。

关键能力：

- 分轨开关：节奏、低音、和弦、旋律。
- 时间线播放。
- 支持用户添加标记。

## 7. 第一版 MVP 范围

如果需要分阶段实现，最小闭环应先证明“感性认知 + 互动学习 + 小创作”的价值：

### MVP 包含

- 第 1 章：音高。
- 第 2 章：音程。
- 第 4 章的一部分：大三和弦与小三和弦。
- 一个最终小型创作实验的雏形。
- 统一的虚拟键盘组件。
- 简单课程导航。
- 每节课一个互动实验和一个小结。

### MVP 不包含

- 用户账号。
- 学习进度云同步。
- 完整编曲器。
- 复杂五线谱系统。
- MIDI 外设输入。
- 复杂音乐版权素材。

### MVP 成功标准

- 一个零基础用户能在 20 到 30 分钟内完成。
- 用户完成后能说清楚：
  - 半音是什么。
  - 音程是什么。
  - 大三和弦和小三和弦为什么听起来不同。
- 所有核心概念都至少有一次可听、可改、可比较的互动。

## 8. 内容表达规范

### 8.1 文案风格

- 使用短句。
- 少用术语堆叠。
- 先说听感，再说概念。
- 避免“你只需要记住”这类教材式口吻。

示例：

- 不推荐：大三度是包含四个半音的音程。
- 推荐：先听 C 到 E。这个距离听起来比较明亮。它跨过 4 个半音，名字叫大三度。

### 8.2 每节课结构

每节课建议固定为：

1. 一个听觉问题。
2. 一个可操作实验。
3. 一组 A/B 对比。
4. 一个简短解释。
5. 一个小判断或小创作。

## 9. 信息架构

### 9.1 顶层页面

- 课程首页。
- 学习界面。
- 实验室。
- 最终作品页。

### 9.2 学习界面布局

建议采用三栏或响应式变体：

- 左侧：课程目录与进度。
- 中间：互动实验区。
- 右侧：当前步骤说明、问题、反馈。

移动端：

- 顶部显示章节进度。
- 中间优先展示互动区。
- 说明区折叠为底部面板。

## 10. 视觉与交互方向

整体气质应接近“艺术展览中的声音装置 + 清晰的音乐工作台”，避免儿童化，也避免传统教材感。

设计关键词：

- 清晰。
- 高级。
- 沉浸。
- 可探索。
- 有声音反馈。
- 有声音可视化。
- 有艺术展览感。
- 有一点录音软件和乐器界面的质感。
- 控制密度适中，不做复杂专业软件。

交互要求：

- 所有可点击音乐元素都必须有即时声音反馈。
- 播放中要有清楚的视觉高亮。
- A/B 对比必须能快速重复播放。
- 用户操作错误时不应提示“错误”，而应引导其重新听差异。

## 11. 技术实现暂定方向

正式技术方案后续单独设计。当前 PRD 只保留方向：

- 纯前端 React。
- 声音合成可使用 Web Audio API 或 Tone.js。
- 不使用 SSR 框架。
- 不依赖后端 API。
- 课程内容应数据化，方便后续扩展章节。
- 章节架构应支持插拔式扩展，新增章节时尽量只新增章节内容和必要的局部互动组件。

## 12. 风险与开放问题

### 12.1 风险

- 课程如果讲太多，会变回传统教材。
- 互动如果太复杂，会让初学者不知道该做什么。
- 声音反馈如果延迟明显，会严重影响体验。
- 概念顺序如果不清楚，用户会记住名词但没有认知变化。

### 12.2 已决策约束

- 不绑定单一音乐风格，优先服务通用音乐素养；示例可以使用足够简单、易识别的旋律或片段。
- 需要加入五线谱，但只教非常基础的读谱能力。
- 需要响应式支持，移动端必须可用。
- 最终作品是一个极小型音乐创作片段，同时保留简单分析能力。
- 课程主语言为中文，并保留英文术语对照。
- 项目为纯前端 React，不使用 SSR，不依赖后端 API。
